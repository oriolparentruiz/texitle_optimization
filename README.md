# 🧵 Textile Factory: Minimum-Length Fabric Roll Planning

Three C++ solvers (**exhaustive search**, **greedy** and **simulated annealing**) for a two-dimensional rectangle packing problem on a fixed-width fabric roll, with the aim of minimising the length of the roll a loom has to produce.

> Project for *Algorísmia i Programació III* (Algorithms and Programming III) · Universitat Politècnica de Catalunya (UPC) · Bachelor's in Data Science and Engineering (GCED) · Academic year 2024–2025
> Authors: **Lucas Viner & Oriol Parent**

---

## 📌 Overview

**Problem:** a textile factory has a single loom that produces one large roll of fabric of width `W` and variable length. Once produced, the roll is cut into the rectangles required by the customers' orders. Given the list of rectangle dimensions, the goal is to compute the **minimum roll length `L`** that fits all the orders and to output **where each rectangle is cut**. Rectangles may be rotated by 90°, must not overlap and must lie entirely inside the roll.

This is a variant of the **2D strip packing problem**, which is NP-hard, so the project compares three algorithmic schemes with different trade-offs between solution quality and running time.

### Input format

The first line contains `W` (roll width) and `N` (total number of rectangles). Each following line has `n_i p_i q_i`, meaning there are `n_i` orders of a `p_i × q_i` rectangle. It is guaranteed that `1 ≤ p_i ≤ min(q_i, W)` and `N = Σ n_i`.

```
4 5
3 1 3
1 3 3
1 1 1
```

### Output format

- Line 1: elapsed time in seconds (at most one decimal) needed to find the solution.
- Line 2: `L`, the length of the roll.
- Then one line per rectangle: `x_tl y_tl x_br y_br` (top-left and bottom-right corners, inclusive). `x` grows left to right in `[0, W-1]` and `y` grows top to bottom in `[0, L-1]`. The order of the lines is irrelevant.

```
3.7
5
0 0 2 2
3 0 3 2
0 3 2 3
0 4 2 4
3 3 3 3
```

## 🔬 Algorithms

| Program | Scheme | How it works | Notes |
|---|---|---|---|
| `exh.cc` | **Exhaustive search** (backtracking) | Rectangles are sorted by decreasing area. For each one, every column `x` is tried in both orientations, placing the rectangle at the lowest free `y` of an occupancy grid. Branches whose current height is already ≥ the best known length are pruned. | Finds the optimum if given enough time. Every improved solution is **immediately written** to the output file, so aborting the program still leaves the best solution found so far. |
| `greedy.cc` | **Greedy** | Rectangles are sorted by decreasing area and placed one by one at the first position (scanning rows, then columns) where they fit inside the current roll, trying both orientations. If nothing fits, the roll is extended with a new row. | Not optimal, but near-instantaneous even on the largest instances. |
| `mh.cc` | **Metaheuristic**: simulated annealing | Starts from a skyline-style constructive solution. A neighbour is generated by relocating 1 to 5 random rectangles to random valid positions. Neighbours are accepted if they improve the cost, or with probability `exp(-Δ/T)` otherwise. Cost is the roll length, with large penalties for overlaps or out-of-bounds placements. | Parameters: `T0 = 1000`, cooling rate `0.99`, up to 10,000 iterations of 500 neighbours each, stopping when `T < 1e-3`. Each improvement is written to the output file as it is found. |

**Time limits used for evaluation:** exhaustive search ≤ 3 minutes, greedy ≤ 5 seconds, metaheuristic ≤ 1 minute.

> ℹ️ The course's public test set and the `checker` binary are not included in this repository. The checker validates the output format, that all rectangles are inside the roll, that the right number of rectangles of each size appears, that there are no overlaps and that `L` matches the rectangles' extent. It does **not** verify optimality.

## ▶️ How to reproduce

**Requirements:** a C++17-capable compiler (e.g. `g++`).

1. Clone the repository:
   ```bash
   git clone https://github.com/<your-username>/<repo-name>.git
   cd <repo-name>
   ```
2. Compile the three programs:
   ```bash
   g++ -O3 -std=c++17 -o exh exh.cc
   g++ -O3 -std=c++17 -o greedy greedy.cc
   g++ -O3 -std=c++17 -o mh mh.cc
   ```
3. Run any of them with an input file and an output file:
   ```bash
   ./exh    instance.txt output_exh.txt
   ./greedy instance.txt output_greedy.txt
   ./mh     instance.txt output_mh.txt
   ```
4. (Optional) Validate the result with the course-provided checker:
   ```bash
   ./checker instance.txt output_greedy.txt
   ```
